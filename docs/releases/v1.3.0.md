# agent-stack-go 1.3.0

A plain `event.Writer` takes the same exclusive file lock as `ChainedWriter`, so
a process that shares a stream with another writer no longer appends over it.
No exported identifier moved: `scripts/api-surface.sh` holds `api/surface.txt`
at its 143 declarations, so every Go consumer builds unchanged.

The minor bump is not for the API. `Write` can now return an error it never
returned before, and it blocks while another writer holds the file lock (see
"Behaviour a consumer can notice"). The same reasoning made 1.2.0 a minor.

## Fixed (agent-stack-go#78): a plain Writer takes the file lock for each append

- **`event.Writer` appends under an exclusive `flock(2)` on the file.** Every
  `Write` takes the lock, appends one line and releases it. Until now only
  `ChainedWriter` locked the file. A plain `Writer` that another process also
  appends to had the same unlocked append, and on an NFS share two appends can
  overwrite one another. The unlocked `ChainedWriter` lost half of two writers'
  events on a shared volume, measured on 2026-10-14 (see 1.2.0). The plain
  writer was not measured on its own.
- Concurrent callers inside one process were already serialized by a mutex; that
  stays. The lock adds exclusion between processes.
- A panic during an append still releases the lock.
- Invariant 28 in `CLAUDE.md` and five scenarios in
  `features/writer-lock.feature`, each bound to a test. Five new tests; all five
  went red on the unfixed writer.

## Behaviour a consumer can notice

- `Write` returns an error and appends nothing when the file cannot be locked.
- `Write` blocks while another writer of the same file holds the lock, for as
  long as that writer's append takes.
- An error from releasing the lock is returned although the line is on disk.
- On Windows there is no cross-process lock, only the same behaviour as before.
  No bus runs there.

## Upgrade notes

- No code change for a consumer: no exported identifier changed. A service that
  writes a shared stream with `event.Writer`, rather than `ChainedWriter`,
  should move to this version so that its appends are serialized with the other
  writers of the file.
- Pin a released tag. The verifier image is
  `ghcr.io/taipanbox/agent-conform:v1.3.0`; there is no `latest`.

## Not proven

- The lock was verified by probes from a second open file of the same path,
  which flock excludes as a second process would. A cross-process loss of the
  plain writer on a real NFS share was not reproduced in this release.
- Durability: `Write` does not fsync, as before.
- Writers outside this library are not covered.

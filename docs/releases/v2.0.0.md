# agent-stack-go 2.0.0

The module moves to its major version path, `github.com/TAIPANBOX/agent-stack-go/v2`,
and with it come the two changes that a consumer or an operator can notice: a stream
is now created `0640` by a writer that owns its directory, and a writer refuses to
create a stream in a directory it does not own. Three additions came in with it: signed
checkpoints for a stream (SPEC 6.5.1), a client for Keyryx's delegated keys, and offline
verification of an agent's own access token.

The exported surface grows by 57 declarations and loses none: `scripts/api-surface.sh`
holds `api/surface.txt` at its 200 declarations, every one of the 143 that 1.3.0 promised
still there, unchanged.

## Breaking

- **The module path is `github.com/TAIPANBOX/agent-stack-go/v2`.** Every package import
  changes. Nothing else in the API moved.
- **Streams are created `0640`.** A writer creates a stream and its checkpoint sidecar
  with mode `0640`, where 1.3.0 created them `0644`. A process that reads a stream it did
  not write, and is neither its owner nor in its group, can no longer open it.
- **A writer refuses to create a stream in a directory it does not own.** An existing
  file is opened as it is. A new stream in someone else's directory is refused with an
  error, and nothing is written.

## Migration

- **Imports.** Change `github.com/TAIPANBOX/agent-stack-go` to
  `github.com/TAIPANBOX/agent-stack-go/v2` in every import and every `require` line, then
  `go get github.com/TAIPANBOX/agent-stack-go/v2@v2.0.0` and `go mod tidy`. A consumer that
  has not moved keeps building against 1.3.0; the two paths are separate modules.
- **Readers of a stream.** A reader outside the owner and the group needs the group, or
  must run as the owner. The launchers now give each producer its own uid, so each stream
  has one owner: stack-single (#138), stack-k8s (#184) and stack-up (#54) carry that change.
- **Directories.** A producer's data directory must be owned by the process that writes
  into it. The launchers create the directories that way.
- **The verifier image.** Pin `ghcr.io/taipanbox/agent-conform:v2.0.0`. There is no
  `latest` tag.

## Added

- **Signed checkpoints (SPEC 6.5.1).** `event.NewChainedWriterWithCheckpoints` writes a
  checkpoint sidecar beside a stream, every 64 lines or 10 seconds, with close and resume
  records and unsigned records on key expiry. `VerifyCheckpoints` gives one verdict per
  record, and an unsigned record is never valid. `VerifyChainRestarts` names each restart
  with the last well-formed line before it.
- **`chain_restarted` in `agent-conform watch-dir`.** A stream whose chain begins again is
  reported as a medium event, or high when no resume checkpoint explains the restart. The
  verifier takes `-checkpoints` and `-checkpoint-keys`, and a refused record exits 1 once.
- **`keyclient`.** A consumer of Keyryx: a delegated key is declared with a life of at least
  ten minutes and renewed at half that life; a held key signs through custody; a key set is
  cached and refused whole if one key in it is bad. Credentials are a unix socket, a key
  file or a projected token. Nothing in `delegation` imports `keyclient`.
- **`delegation.VerifyAccess` and `VerifyRelayedAccess`.** An agent's own access token (RFC
  9068, `typ` `at+jwt`, DPoP-bound) is verified offline, with the checks in the order
  tokenfuse applies them. `ReplayCache` is the two-generation proof cache behind it.
  `delegation/testdata/agent-token-vectors.json` is the shared table, 59 cases and 6 replay
  sequences, found by its `$source` so a tokenfuse suite can vendor it byte for byte. A
  claim that the Rust deserializer cannot read (an `iat` or `exp` that is not a whole
  second, a unit or org that is not a string) is refused here too.

## Fixed

- A stream can no longer be created with a mode that lets any local user read it, and a
  writer can no longer create a file in a directory another user owns. Both are the
  `0640` and foreign-directory changes above; they close a read of agent records by
  unrelated local users and a write into a producer's directory by one.

## Not proven

- Root signatures on keyclient's statements are not checked by this package. Trust in a
  statement and in a key set is the transport to custody.
- The 0640 change is verified by this module's tests. The launchers' own uid split is
  verified in their repositories, not here.
- Durability: writes are not fsynced, as before.

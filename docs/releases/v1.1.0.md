# agent-stack-go 1.1.0

A new CLI mode and the first published `agent-conform` image. The Go library
API is unchanged: no exported identifier of `chain`, `delegation`, `event` or
`passport` moved, and `scripts/api-surface.sh` holds `api/surface.txt` at its
143 declarations. The minor bump is for the new command-line surface and the
image, not for the library. This release was approved by the owner.

## Added (agent-stack-go#66, closes #64 on the repository side)

- **`agent-conform watch-dir [-out PATH] [-state PATH] [-every D] <dir>`**, a
  chain verifier that runs on a box and alerts. It walks every `*.ndjson` in
  one flat directory (not recursive, symlinks skipped), verifies each file's
  `prev_hash` chain with `event.VerifyChain`, and appends one agent-event per
  new finding to its own chained stream:
  - `chain_broken` (high): the file, the line of the first break, the kind
    (`prev_hash_mismatch`) and the count of breaks.
  - `chain_unchained` (low): two or more events and no `prev_hash` at all. Not
    a break.
- Each `(file, kind, line)` is announced once, through a state file written
  after the event. Exit codes: 0 nothing new, 1 a new break, 2 usage or I/O
  error (2 wins). A missing or empty bus is an error, never a quiet pass.
- It writes only its own output and state, never modifies a file it reads,
  refuses an output named like another writer's stream, and reads with a line
  cap (1 MiB, at most 4 MiB) and a file cap (256 MiB). A file over the cap is
  never a clean pass, and a forged `prev_hash` is clipped so it cannot inflate
  an alert.
- `-every` (at least 10s) loops in one process, because the image base has no
  shell to loop in, and exits 2 the moment a pass cannot do its job so a
  supervisor shows it.
- **The `agent-conform` image**, `ghcr.io/taipanbox/agent-conform:<tag>`,
  published by `release.yml` on a `v*` tag only: `linux/amd64` and
  `linux/arm64`, static, distroless, non-root (uid 65532), both base images
  pinned by digest (`scripts/base-images-pinned-by-digest.sh`), signed by
  digest with keyless cosign and carrying a build-provenance attestation.
  There is no `latest`. A pull request touching the Dockerfile or the
  workflow builds the image without pushing.
- Invariants 25 and 26 in `CLAUDE.md`, a README section with compose and
  CronJob snippets, and the Dockerfile half of `scripts/reproducible-build.sh`.

## Upgrade notes

- **Library consumers need no change.** The module's exported surface is the
  same as 1.0.2, so a service pinned to 1.0.2 can move to 1.1.0 with no code
  edit; `go get github.com/TAIPANBOX/agent-stack-go@v1.1.0`. Nothing forces
  the move, since 1.0.2 and 1.1.0 behave the same for a library user.
- `agent-conform`'s existing modes (`-chain`, the passport and event checks)
  are unchanged; `watch-dir` is a new subcommand.
- To run the verifier from the image, mount the bus read-only, put the
  verifier's own stream and state on a writable volume, and run it as the uid
  that owns that volume. The README's "Running the chain verifier on a box"
  section has the compose and CronJob forms. Pin a released tag, never a
  moving one.
- The image's name `ghcr.io/taipanbox/agent-conform` is new. No launcher runs
  it yet; that is a change in each launcher.
- Release asset names still carry no version (invariant 12), so existing
  `releases/latest/download/<name>` links keep resolving.

## Not proven

- Not run on a live bus where writers append while it reads, nor on a box;
  only a fixture copy, in a locally built arm64 image.
- The README's compose and CronJob snippets were not applied to anything.
- The amd64 build, the multi-arch push, `cosign sign` and the provenance
  attestation of the image run for the first time on this tag.
- A stripped `prev_hash` reads as a chain restart and a garbled line leaves
  the next one unverifiable; neither raises an alert (both are counted in the
  alert's data), because a crash mid-write produces the second shape. A writer
  forging its own stream with a valid chain, and truncation from the end, are
  invisible.
- Only the first break per file is announced; a later break is not until the
  first is gone, and the same line broken again after a repair is not
  re-announced.
- Image bytes are not claimed to rebuild identically; the reproducibility
  claim covers the release archives.
- Follow-ups outside this repository: the agent-passport SPEC section 6.2
  has no `agent-conform` row, and the estate gates C4 and C20 will report the
  new producer and the new image until each learns about them.
